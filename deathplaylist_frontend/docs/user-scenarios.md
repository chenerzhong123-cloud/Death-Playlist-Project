# 死亡歌单 — 用户使用场景文档

## 产品概述

死亡歌单是一款社交趣味类应用，用户可以为自己"策划"一场专属葬礼音乐清单——选择喜欢的歌曲、试听预览、编写个人简介、生成精美的分享卡片，还可以浏览朋友们的歌单。产品以轻松幽默的方式切入死亡话题，降低讨论门槛。

---

## 用户角色

| 角色 | 说明 |
|------|------|
| **新用户** | 未授权微信登录的访客，可浏览朋友歌单，但无法创建歌单 |
| **已登录用户** | 已完成微信授权的用户，可创建、编辑、分享自己的歌单 |
| **浏览者** | 通过分享链接/H5页面进入的访客，查看他人的歌单内容 |

---

## 场景一：首次进入与授权登录

**触发条件**：用户首次打开应用

**前置状态**：用户未登录

**操作流程**：

1. 用户进入应用，看到落地页，展示：
   - 应用图标（圆形线框风格音符图标）与标题「死亡歌单」
   - 副标题引导文案：「不想自己的葬礼还在吹唢呐放哀乐？选择你的葬礼上播放的音乐吧」
   - 三个操作入口：「新的歌单」「看朋友们的歌单」「点赞投币」
2. 页面加载 800ms 后，若用户未登录，自动弹出**授权弹窗**：
   - 顶部绿色圆形微信图标
   - 标题「微信授权」
   - 说明文字：「申请获取您的公开信息（昵称、头像等）」
   - 两个按钮：「允许」（绿色）、「拒绝」（灰色）
3. 用户点击「允许」→ 系统模拟微信授权，Toast 提示「授权成功」，弹窗关闭
4. 用户点击「拒绝」→ 弹窗关闭，用户仍可浏览落地页，但未登录状态会影响后续功能

**预期结果**：用户完成授权，可以开始创建歌单

**异常情况**：当前为模拟登录，无真实授权失败处理；拒绝授权后弹窗不会再次自动弹出

## 场景二：创建歌单 — 搜索、试听与选择歌曲

**触发条件**：用户点击落地页「新的歌单」按钮

**操作流程**：

1. 用户进入歌单编辑页，页面分为上下两个区域：
   - **上方**：歌曲搜索区，展示可搜索的歌曲列表
   - **下方**：已添加歌曲区（初始为空），显示「已添加 (0/9)」
2. 用户通过搜索栏输入关键词（支持按歌名或歌手名模糊搜索）
3. 搜索结果实时过滤展示，未匹配时显示「未找到相关歌曲」
4. 每首歌曲右侧有两个操作按钮：
   - **播放/暂停按钮**（左）：点击试听歌曲，图标切换为暂停状态；再次点击停止
   - **添加按钮**（右，「+」/「✓」）：点击添加到歌单
5. 用户点击「+」添加歌曲：
   - 按钮变为白色「✓」状态
   - 歌曲同步出现在下方「已添加」列表（带缩放淡入动画）
6. 已添加列表中每首歌也有**播放/暂停按钮**和**移除按钮**（×）
7. 当已添加 9 首歌曲时，再次添加触发 Toast 提示「最多只能添加9首音乐哦」
8. **迷你播放器**：选中歌曲播放后，页面底部滑出播放器条：
   - 显示专辑封面（带呼吸动画）、歌名、歌手
   - 暂停按钮可停止播放
   - 模拟进度条（自动推进，非真实音频）
9. 点击返回按钮时，播放器自动停止
10. 点击「完成」时，播放器自动停止，进入预览页

**业务规则**：
- 歌单上限：9 首歌曲
- 支持搜索，但不支持外部分享链接导入
- 当前歌曲库为 Mock 数据（10 首预设歌曲）
- 音乐播放为模拟（视觉反馈，无真实音频输出）

**预期结果**：用户完成歌曲选择，点击右上角「完成」进入预览页

**异常情况**：
- 未添加任何歌曲时点击「完成」→ Toast 提示「请先添加至少一首歌曲」

## 场景三：预览与编辑歌单

**触发条件**：在歌曲选择页点击「完成」（已添加至少 1 首歌曲）

**操作流程**：

1. 用户进入预览页，展示：
   - 标题：「{用户昵称}的死亡歌单」
   - 简介：可编辑区域，默认提示「点击输入简介，15字以内」
   - 歌曲列表（带序号，如 01、02...）
2. 用户点击简介区域，进入编辑模式：
   - 显示输入框，最多输入 15 个字符
   - 按 Enter 或点击其他区域退出编辑
3. 用户长按歌曲可拖拽排序（通过 Reorder.Group 实现）
4. 底部两个操作：
   - 「上一步」：返回歌曲选择页
   - 「分享预览」：进入分享卡片页

**业务规则**：
- 简介字数上限：15 字
- 歌曲排序通过拖拽完成，无数字输入排序

**预期结果**：用户确认歌单内容和顺序，准备分享

---

## 场景四：生成分享卡片

**触发条件**：在预览页点击「分享预览」

**操作流程**：

1. 用户进入分享页，展示一张手机外形的精美卡片：
   - 卡片背景使用预设背景图（半透明叠加）
   - 标题：「{用户昵称}的死亡歌单」
   - 个人简介文字
   - 歌曲列表（序号 + 歌名 + 歌手）
   - 底部区域：品牌标识「死亡歌单」+ 二维码（扫码查看完整歌单）
2. 卡片下方提供两个分享操作：
   - **保存**：将卡片保存到相册（当前为 Toast 模拟提示「已保存到相册」）
   - **微信好友**：唤起微信分享（当前为 Toast 模拟提示「正在打开微信...」）
3. 点击「返回预览」可回到上一页

**预期结果**：用户成功生成并分享歌单卡片

**备注**：
- 二维码通过第三方 API（qrserver.com）实时生成，内容为当前页面 URL
- 保存和分享功能在 MVP 阶段为模拟实现

## 场景五：浏览朋友歌单

**触发条件**：在落地页点击「看朋友们的歌单」

**前置状态**：无需登录，任何用户均可浏览

**操作流程**：

1. 用户进入朋友歌单列表页
2. 展示多位朋友的歌单卡片，每张卡片包含：
   - 头像 + 昵称 + 歌单标题
   - 个人简介（带引号，斜体展示）
   - 歌曲列表（专辑封面 + 歌名 + 歌手）
3. 用户上下滚动浏览所有朋友的歌单
4. 滚动到底部显示「没有更多朋友的歌单了」
5. 点击左上角返回按钮回到落地页

**预期结果**：用户浏览朋友们的歌单内容

**当前数据**：3 位 Mock 用户（阿强、小雅、老李）

## 全局交互说明

| 项目 | 说明 |
|------|------|
| **Toast 提示** | 全局通知机制，底部居中显示，2 秒后自动消失，白底黑字圆角胶囊样式 |
| **页面转场** | 所有视图切换带有 Framer Motion 动画（淡入淡出、滑动、缩放） |
| **背景效果** | 全局背景图 + 黑色 60% 遮罩 + 2px 模糊 + 底部渐变，营造暗色氛围 |
| **设计风格** | 毛玻璃（glassmorphism）风格，`backdrop-blur` + `bg-white/` 半透明叠加 |
| **迷你播放器** | 在歌曲选择页底部滑出，展示当前播放歌曲信息 + 模拟进度条，离开页面时自动停止 |

## MVP 阶段限制

以下功能在当前版本中为**模拟实现或未完成**：

- 微信授权登录：模拟为直接设置昵称，自动弹窗授权（无真实微信 OAuth）
- 歌曲数据：使用 10 首 Mock 歌曲，未接入真实音乐 API
- 音乐播放：仅有视觉模拟（进度条动画），无真实音频播放
- 朋友数据：使用 3 位 Mock 用户，无真实社交关系
- 保存到相册：仅 Toast 模拟，未实现真实保存
- 分享到微信：仅 Toast 模拟，未调用微信分享 SDK
- 点赞投币：按钮存在但未绑定功能
- 背景图配置：设置面板已移除，背景图固定为默认值
- 后端服务：无后端，所有数据存储在前端状态中（刷新即丢失）
